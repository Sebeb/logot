The retained engine banner identifies 4.7.2.stable.official.ed1daf0bf. At that exact source revision, [Control::set_rotation](https://github.com/godotengine/godot/blob/ed1daf0bf/scene/gui/control.cpp#L1519) invokes transform invalidation without item_rect_changed. [CanvasItem](https://github.com/godotengine/godot/blob/ed1daf0bf/scene/main/canvas_item.cpp#L1078) stops inherited propagation at an already-dirty node. Enabling notifications resolves the cache only on a flag transition. Its global-transform getter clears the dirty state. [SceneTree::flush_transform_notifications](https://github.com/godotengine/godot/blob/ed1daf0bf/scene/main/scene_tree.cpp#L186) removes queued entries and delivers notifications without clearing that cache. The process path flushes notifications around frame processing. [Node2D](https://github.com/godotengine/godot/blob/ed1daf0bf/scene/2d/node_2d.cpp) supplies no native transform-notification handler that resolves it.

Logot's observer previously only forwarded invalidation. Sampling reads row transforms rather than the observer's transform, leaving the nonvisual child dirty. Subsequent row changes therefore cannot reliably enqueue its callback. The display's constant-cost fallback samples its own transform, which stays unchanged for an independent row rotation. More deferred frames or periodic whole-row polling would not correct that ownership mistake.

The authorized fix changes only the existing PinnedOccupiedTransformObserver callback in addons/logot/logot_display.gd: for a transform notification while inside the tree and not queued for deletion, evaluate the observer's own get_global_transform() before calling the valid invalidation callable. The rest of the API, four viewport-space AABB unions, row layout/preferences, coalesced sampler and O1 display fallback remain unchanged. This re-arms the targeted observer after entry/reparent and each inherited dirty transition. It adds no signals or polling and does not change coordinates.

The extended focused case preserves every original check, including the failing rotation assertion. It adds consecutive independent rotations toward zero, to zero, and away again, with requested-angle premises, exact row-geometry comparisons and one-publication checks after settled frames. A further independent rotation checks the same observed row after tree exit/re-entry and layout reparenting. Existing display processing is paused only within those new sequences, explicitly asserted, so periodic container layout cannot reset the test angle or substitute for the observer. The case never primes the observer's cache itself.
